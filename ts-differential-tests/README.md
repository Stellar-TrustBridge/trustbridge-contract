# TypeScript Differential Tests

Differential tests that verify the Stellar TypeScript SDK decodes TrustBridge
contract XDR outputs correctly, catching ABI drift after Rust changes.

## Purpose

After any wave of Rust changes, the TypeScript bindings generated by
`stellar contract bindings typescript` can drift from the actual contract ABI.
These tests catch that drift by:

1. Generating XDR fixtures from Rust contract tests (`tests/generate_xdr_fixtures.rs`).
2. Decoding those XDR fixtures using `@stellar/stellar-sdk`.
3. Asserting decoded field values match golden values in `.address` / `.meta.json` sidecars.

Fixture files that have not been generated yet are placeholders (start with `#`).
Placeholder fixtures are **skipped** rather than failed, so CI stays green until the
generator is run.

## Prerequisites

- Node.js ≥ 18 (for `node:test` and `node:assert/strict`)
- `npm install` (installs `@stellar/stellar-sdk`)
- Rust + Cargo (only needed to regenerate fixtures; not needed to run the TS tests)

## Setup

```bash
npm install
```

## Running Tests

```bash
# Run all differential tests:
npm test

# Verbose output:
node --test --test-reporter=spec fixtures.test.js
```

## Generating / Regenerating Fixtures

Run this whenever the contract ABI changes (new fields, type changes, new events):

```bash
# From the repo root:
make xdr-fixtures

# Or manually:
cargo test generate_xdr_fixtures -- --ignored --nocapture
# Then paste each printed block into the matching file under fixtures/.
```

See `fixtures/README.md` for the full list of fixture files and what each test asserts.

## Test Structure

`fixtures.test.js` uses Node's built-in `node:test` runner (`describe` / `it`).
Each `it` block:

1. Tries to load the `.xdr` fixture file.
2. Skips with `t.skip()` if the file is a placeholder.
3. Decodes the XDR using the Stellar SDK.
4. Asserts structural invariants (field presence, correct XDR type).
5. If a `.meta.json` sidecar exists, asserts exact field values against it.

Two structural tests always run regardless of fixture state:
- `XDR ScVal round-trips cleanly through the SDK` — catches a broken SDK import.
- `Address round-trips through ScAddress` — catches a broken Address import.

## Fixtures Covered

| Fixture | What it tests |
|---------|---------------|
| `get_address_octocat` | `ContributorRecord` decode — `stellar_address`, `registered_at` (u32), `verified` (bool) |
| `batch_remove_proposed_event` | `BatchRemoveProposedEvent` — `proposed_by`, `count`, `timestamp`, `domain` |
| `batch_remove_executed_event` | `BatchRemoveExecutedEvent` — `executed_by ≠ proposed_by`, `successful ≤ count`, `domain` |
| `batch_remove_cancelled_event` | `BatchRemoveCancelledEvent` — `cancelled_by`, `proposed_by`, `timestamp`, `domain` |

## CI Integration

The `differential-tests` job in `.github/workflows/ci.yml` runs `npm test`
automatically on every PR. The two structural tests always run; the fixture-based
tests skip cleanly when fixtures are placeholders and pass when fixtures are present.
